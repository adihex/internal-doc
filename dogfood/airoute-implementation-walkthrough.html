Purpose and boundaries

airoute V1 is a local TypeScript/Node 20 CLI that classifies task text, builds an eligible provider set, ranks routes deterministically, explains the choice, and launches the selected official native CLI. It is subscription-aware without proxying model traffic or reading OAuth tokens. The canonical statement is README.md:1-9; the safety contract is docs/SPEC.md:1-22.

note Non-goals are as important as features: V1 is not a model API proxy, daemon, workflow orchestrator, worktree manager, quota scraper, autonomous policy tuner, or generic executable-plugin host.

  1. Read task text from an argument or stdin and normalize it locally (`src/cli.ts:126-134`, `src/classifier.ts:39-41`).
  2. Classify role, complexity, risk, domain, scope, reasoning, confidence, and explainable lexical signals (`src/classifier.ts:9-111`).
  3. Merge global and repository TOML configuration, then combine adapter declarations, executable presence, and provider-state projection (`src/config.ts:43-78`, `src/cli.ts:85-123`).
  4. Filter mode capabilities and optional provider overrides before deterministic policy ranking (`src/cli.ts:147-183`).
  5. For a run, record a sanitized decision, construct separate executable and argv values, and supervise the immediate child (`src/cli.ts:231-302`, `src/adapters.ts:194-219`, `src/runner.ts:51-108`).
  6. Append sanitized outcomes and only record fallback after a replay-safe pre-execution admission switch (`src/cli.ts:292-313`).

The modules are intentionally narrow: classifier and policy are pure; adapter declarations own native contracts and fit priors; runner owns process/fallback safety; store owns durable facts; CLI composes them. docs/ARCHITECTURE.md:21-29 documents this ownership map.

Classifier and TaskProfile

TaskProfile is a versioned typed record with role, complexity, risk, domain, scope, reasoning, confidence, and signals (src/types.ts:1-27). classifyTask uses bounded weighted lexical rules, Unicode normalization, explicit negated-write handling, and deterministic tie-breaking by score then role name (src/classifier.ts:9-40).

Quality-first policy and balancing tolerance

Policy version airoute.quality-first.v1 computes quality from task fit, reasoning, domain, and scope with weights 35%, 25%, 20%, and 20%. The displayed total score is 80% quality and 20% availability (src/policy.ts:3,19-42). Selection is deliberately stricter than simply sorting that total: materially lower-quality candidates stay behind, while availability can reorder only candidates within quality_tolerance, default 0.05 (src/policy.ts:44-54, src/config.ts:14-19).

quality = 0.35·fit + 0.25·reasoning + 0.20·domain + 0.20·scope
display total = 0.80·quality + 0.20·availability
selection = quality band first; availability breaks ties inside tolerance
  • Disabled routes excluded: true
  • Missing executables excluded: true
  • Paused routes excluded: true
  • Known utilization at or above 1 excluded: true
  • Unknown quota treated as neutral 0.5: true
  • Availability may displace materially better quality: false

test/policy.test.ts:45-92 verifies materially better quality wins, balancing happens inside tolerance, unknown quota is neutral, and ineligible routes never re-enter selection. Scores are configurable priors rather than universal model claims (README.md:48-55).

Safe process launching and environment handling

prepareLaunch returns a typed PreparedLaunch with executable and argv separated, shell: false, a sanitized environment, and a manual-prompt marker (src/types.ts:69-75, src/adapters.ts:194-219). spawnSupervised passes those values directly to child_process.spawn, inherits stdio for native terminal behavior, forwards SIGINT/SIGTERM to the immediate child, and removes listeners when complete (src/runner.ts:51-108). No shell string or eval is involved.

spawn(prepared.command, prepared.args, {
  shell: false,
  stdio: "inherit",
  env: prepared.env,
});

Environment sanitization removes known direct-model API keys and endpoint overrides while retaining PATH, HOME, terminal variables, native config homes, and keychain access needed by official subscription authentication (src/adapters.ts:150-169). The hostile-looking task fixture in test/adapters.test.ts:39-62 proves quotes and shell metacharacters remain one argv element, and test/adapters.test.ts:81-90 verifies credential override removal.

warning Some native CLIs require task text in argv, which same-user process inspection or OS audit tooling may observe. Sensitive tasks should use interactive native entry where possible. Airoute forwards signals only to the immediate child; the harness owns descendants.

executeWithFallback encodes the boundary in this order: success returns; any started failure raises PARTIAL_EXECUTION; any write-risk pre-start failure raises SWITCH_APPROVAL_REQUIRED; read-only fallback continues only for quota, auth, or missing-executable admission failures (src/runner.ts:11-48). spawnSupervised trusts an admission outcome as pre-start only when the adapter declares the exact exit code (src/runner.ts:84-100). test/runner.test.ts:14-86 covers all three branches and the declared-code requirement.

Advisor and proposal boundary

History, event export, observed metrics, and deterministic policy replay expose evidence without granting self-modification (src/cli.ts:378-440,471-515). Metrics explicitly warn that observed outcomes are not counterfactual; replay changes selection under current policy but cannot estimate unchosen outcomes.

  • Minimum baseline samples: 3
  • Minimum amendment samples: 3
  • Minimum evidence event IDs: 3
  • Minimum improvement: positive
  • Allowed severe regressions: 0
  • Approval: required

The strict Zod proposal schema is src/proposal.ts:3-29; validation returns data but never applies changes (src/proposal.ts:31-34, src/cli.ts:516-522). test/proposal.test.ts:4-33 accepts an evidence-gated approval-only proposal and rejects automatic promotion or insufficient evidence.

Known limitations

  • Classifier is lexical rather than semantic: true
  • Quality values are user-configurable priors, not universal truth: true
  • Quota commonly remains unknown without a non-spending official probe: true
  • Amp interactive mode requires manual prompt paste: true
  • Read-only is available only when a native adapter can enforce it: true
  • Signal forwarding covers only the immediate child: true
  • Task argv may be visible to same-user OS inspection: true
  • Windows state/config behavior is fully native beyond XDG override: false
  • Real auth, quota, TTY, and subscription behavior proven in build orb: false

Additional intentional limits: no arbitrary executable adapters before signing/versioning/security semantics; no counterfactual outcome inference; no auto-applied proposals; no claimed ACP for Antigravity; and no replay after ambiguous execution. See README.md:69-84, docs/ARCHITECTURE.md:21-29, and docs/SMOKE.md:14-18.

Safe local Mac test plan

  1. Use a disposable repository and install with Node 20 or newer; run `npm ci` and `npm run check` before linking the CLI.
  2. Run `airoute providers --json` and confirm Cursor is disabled by default even if `agent` exists.
  3. Run `airoute doctor --json`; inspect only official status/auth probe results. Treat `unknown` as unknown, not success or available quota.
  4. Run `airoute explain` on representative read-only, localized-write, and broad-write text; verify profile signals and quality-band ordering without launching a harness.
  5. Run `airoute run` with `--dry-run --json` and, for read-only admission, `--read-only`; confirm only adapters declaring native read-only remain.
  6. Inspect state under `~/Library/Application Support/airoute/state`: permissions should be private and events must contain no task text, source, transcript, or credential.
  7. Only after reviewing the dry run, test a real interactive read-only task in the disposable repository. Approve no writes and verify TTY behavior, task handoff, and signal forwarding manually.
  8. Simulate admission/failure behavior with fake local executables, not paid provider calls; verify read-only pre-start fallback, write stop, and no replay after start.
